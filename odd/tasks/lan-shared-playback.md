# LAN Shared Playback

## Objective
Allow a host PC to select files or a folder through the existing browser UI, upload the selected media into a temporary local-server session, and let LAN clients play the same media in synchronized shared playback with bidirectional controls.

## Problem
The current browser-selected `File` objects and `blob:` URLs exist only in the host browser. The static Node server cannot serve them to other LAN clients, and all playback state is browser-local.

## Scope
- Preserve the existing host file/folder picker as the media-selection entry point.
- Upload selected media from the host browser to the local Node server.
- Serve uploaded media by opaque IDs with HTTP byte-range support.
- Bind the server to a LAN-accessible interface and expose a protected room URL.
- Synchronize selected media, play/pause, seeking, navigation, and playback rate between connected clients.
- Keep volume, mute, fullscreen, wake lock, and visual UI preferences client-local.
- Delete temporary uploaded media when the server stops.

## Constraints
- No arbitrary filesystem paths accepted from clients.
- No new production dependency unless the implementation demonstrates it is necessary.
- LAN access requires a per-server unpredictable room token.
- Direct browser playback only; transcoding, remuxing, subtitles, QR discovery, and Internet access are out of scope.
- Existing local-only behavior must remain usable.
- User has not authorized commits; record validation evidence but do not commit.

## Acceptance criteria
- A host can choose files or a folder through the current UI and the server stores them in a temporary session.
- A LAN client with the room URL can browse the server playlist and play media served by Node.
- Seeking works through compliant HTTP range responses.
- Play, pause, seek, previous, next, and selection initiated from either client converge on all clients.
- LAN requests without the valid room token cannot access media, room state, or controls.
- Temporary session media is cleaned up on ordinary server shutdown.

## Checks
- Focused server/API tests for upload validation, token enforcement, media range responses, and room-state commands.
- Focused browser/manual integration check with two browser clients on one machine or LAN when available.
- Existing applicable test/lint commands discovered from the repository.
